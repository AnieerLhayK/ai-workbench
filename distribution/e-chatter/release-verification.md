# Release verification

Use synthetic text and roles only. Never attach a credential file, personal
corpus or user library to an acceptance receipt. A release receipt identifies
the exact source_revision and version, with checks named codex_real,
deepseek_account_real, deepseek_key_real, clean_windows11. Each check has
`passed: true` and a nonempty `evidence` description before a stable version is
allowed. Missing checks keep the version a release candidate.

On a fresh Windows 11 x64 ordinary-user machine without Python, Node, Workspace
or personal Agent state: verify the downloaded ZIP hash, extract under a Chinese
path containing spaces and launch. Check the empty library, both themes,
restart persistence and missing-Agent guidance. Install the chosen official
Agents, perform account login/Key setup, select model/effort and generate
synthetic text. Verify streaming, cancel, reconnect and restart. Import a minimal
role, switch roles with confirmation, invoke Generator/Maintainer and doctor,
review a proposal and save a new version without changing original hashes.
Export/import a migration package and verify no credential material. Retain
redacted evidence and environment identity outside source.

Upgrade a synthetic old library using --data. Confirm sessions, classifications,
versions and records remain, including failure recovery and settings. Reopen
the old executable only where its documented data format is compatible; never
automatically downgrade or rewrite library files during rollback.

The earlier post-login connection-ended notification was observed while the
account status was connected. Repeated status reads and a subsequent real
generation did not reproduce it; its cause remains unconfirmed. Failures now
report a safe process exit code where available, without raw provider output.
For recurrence record the application version, action, phase and safe error
code; do not export credentials or authorization URLs.
