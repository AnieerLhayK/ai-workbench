# ai-workbench maintenance

This package owns personal helper source, tests and portable documentation.
In an authoritative Workspace checkout, inherit root governance, register its
task before writes and resolve `ai_workbench_development`; real integration and
public projection changes use their dedicated routes. Host commands and task
records apply only there. In a standalone clone, inspect Git state and follow
the clone's task/permission rules. Develop and run the README's simulated tests
without a Workspace CLI or private host files. External contributions return
to Workspace for review and synchronization by its registered publisher.

Read [the maintenance contract](shared/maintenance.md) before changes. Load
[the maintenance skill](skills/ai-workbench-maintainer/SKILL.md) when developing,
testing or preparing a projection. It is development-only and unexposed here.

Keep demo mode explicit. Preserve independent tool state and callback-based
completion. Local deployment and real controls use their own approved host task;
ordinary maintenance does not grant process, account or external authority.
Do not claim a timer completion or a live installer verifies service readiness.
Keep temporary outputs outside source, in host staging or an external temp
directory. Delivery evidence must identify runtime, relevant tests, native
review for GUI changes, payload checks for export changes and unverified real
integration. Read the skill's projection workflow when changing public contents.
